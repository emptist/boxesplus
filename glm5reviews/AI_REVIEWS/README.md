## 🔍 审查方法

### 实践驱动的审查

核心理念："实践出真知"

通过实际编写和测试代码，我们能够：
1. 深入理解API的设计意图
2. 发现潜在的使用问题
3. 评估代码的可维护性
4. 提出切实可行的改进建议

### 审查流程

1. **阅读代码** - 理解项目结构和设计
2. **实践验证** - 在工作间中实现类似功能
3. **对比分析** - 对比主项目和实践代码
4. **发现问题** - 识别潜在问题和改进点
5. **提出建议** - 基于实践经验提出改进建议
6. **编写报告** - 整理发现和建议，形成报告

## 💡 使用建议

### 对于AI Reviewer

1. **保持客观** - 基于事实和代码，避免主观判断
2. **提供示例** - 用代码示例说明问题和改进方案
3. **优先级明确** - 标注问题的严重程度和改进的优先级
4. **可操作建议** - 提出具体、可执行的改进建议
5. **持续更新** - 随着项目发展，定期更新审查报告

### 对于项目维护者

1. **重视错误处理** - 添加参数验证和try-catch
2. **减少代码重复** - 提取共享逻辑到工具模块
3. **完善文档** - 为所有函数添加JSDoc注释
4. **统一命名规范** - 使用一致的命名风格
5. **添加单元测试** - 提高代码质量和稳定性
